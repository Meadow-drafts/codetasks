# 1. PROJECT OVERVIEW

CodeTasks is a VS Code extension that scans source-code comments such as:

* TODO
* FIXME
* BUG
* HACK
* REFACTOR
* TASK

and turns them into manageable tasks inside a VS Code webview-based UI.

The extension allows users to:

* scan source files for tasks
* display tasks
* search tasks
* filter tasks
* sort tasks
* update task status
* update task priority
* view tasks in a table
* view tasks in a Kanban board
* drag tasks between Kanban status columns
* open a task's source location
* open a task detail page
* edit task information
* archive tasks
* unarchive tasks
* persist task state between extension sessions

The architecture is primarily:

```text
Source Files
    ↓
Scanner
    ↓
Scanned CodeTask[]
    ↓
TaskStore
    ↓
Reconciler
    ↓
Persistent Workspace State
    ↓
Workspace Webview / Task Detail Webview / Other UI
```

The `TaskStore` is the central source of truth.

# 2. IMPORTANT CURRENT ARCHITECTURAL PRINCIPLE

There are two different concepts:

## Scanned tasks

These are the tasks discovered from source files.

## Stored task state

The user can modify properties of scanned tasks, such as:

* status
* priority
* description
* archive state
* timestamps

Therefore, when scanning happens again, the scanner must NOT blindly replace existing task state.

The reconciler exists specifically to preserve user-managed state.

The current reconciler is conceptually:

```ts
export function reconcileTasks(
  scannedTasks: CodeTask[],
  existingTasks: CodeTask[],
): CodeTask[] {

  const existingById = new Map(
    existingTasks.map((task) => [task.id, task]),
  );

  return scannedTasks.map((scannedTask) => {

    const existingTask =
      existingById.get(scannedTask.id);

    if (!existingTask) {
      return scannedTask;
    }

    return {
      ...scannedTask,

      status: existingTask.status,
      priority: existingTask.priority,
      createdAt: existingTask.createdAt,
      updatedAt: existingTask.updatedAt,
      archivedAt: existingTask.archivedAt,
    };
  });
}
```

Preserving `archivedAt` here is intentional.

# 5. ACTIVE VS ARCHIVED TASKS

This is extremely important.

The store already has:

```ts
getActiveTasks(): CodeTask[] {
  return this.tasks.filter(
    (task) => !task.archivedAt
  );
}
```

and:

```ts
getArchivedTasks(): CodeTask[] {
  return this.tasks.filter(
    (task) => !!task.archivedAt
  );
}
```

Therefore:

```text
archivedAt === undefined
```

means the task is active.

And:

```text
archivedAt !== undefined
```

means the task is archived.

The workspace/task list should normally use:

```ts
getActiveTasks()
```

not:

```ts
getTasks()
```

unless the UI explicitly represents all tasks.
